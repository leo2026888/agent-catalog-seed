# 评测方法（提案 v0.1）

本文是 `agent-catalog-seed` 的早期评测方法提案。仓库中的方法、字段和示例不代表已经完成的评测，也不构成安全认证、平台认可或效果保证。正式条目结构以[版本化 schema](../schema/entry.v0.1.0.schema.json)为准；报告使用[评测模板](../templates/evaluation-report.md)。

## 1. 一个结论必须回答什么

任何评测结论都必须说明：评了哪个制品、在什么环境、按什么场景、何时评测、运行了多少次、观察到什么、还有哪些未知。脱离这些条件的“安全”“最好”“支持所有平台”不属于合格结论。

每份报告至少绑定：

- 条目 ID、发布版本、源代码提交号（若可得）、下载来源与实际测试制品的 SHA-256；仅记录可变化的仓库 URL 不够。
- 操作系统与架构、宿主/客户端及版本、适配器版本、模型供应方和模型标识、可得的模型版本或快照、关键参数与依赖版本。供应方未公开版本时明确填写“未公开”，不能推断。
- 场景与测试数据的版本或摘要、网络条件、工具权限、外部服务和环境变量名称；报告中不包含密钥值。
- 开始和结束时间、时区、评测者、与作者或赞助方的关系、报告版本。
- 原始记录或可审阅的脱敏证据、复现步骤、失败记录、费用与耗时的计量口径。

若制品摘要或关键测试环境无法确认，结论降为来源受限的观察，不能记为已完成的可复现运行评测。

## 2. 证据层级与边界

以下层级描述证据来源，不是从差到好的安全等级。条目可以同时包含不同来源的证据，必须分别展示，不能将它们混成一个评分。

| 证据状态 | 最低要求 | 允许陈述 | 不足以支持的陈述 |
| --- | --- | --- | --- |
| 未评测 / 作者声明 | 有来源和采集时间；主张注明由作者提供 | “作者声明支持 X，尚未验证” | “已支持 X”“安全可用” |
| 静态检查 | 固定制品摘要；说明检查文件、工具版本、规则和人工范围；列出遗漏 | “在列明范围内发现/未发现指定模式” | 没有恶意行为、运行无风险、效果达标 |
| 运行观察 | 固定制品；隔离环境；批准的权限；版本化场景；全部运行与失败记录 | “在所列宿主与场景中，N 次中 M 次达到预设标准” | 所有平台兼容、长期可靠、未测能力有效 |
| 社区观察 | 来源、时间、所用版本与环境（未知即注明）；利益关系；重复报告处理 | “收到若干份独立或待核实的观察” | 将赞数、下载量或作者自报当作独立评测 |

“待复核”“已过期”“因安全疑点暂停推荐”是报告或展示状态；不能删除曾经的失败结果来提升条目形象。没有发现问题必须同时展示检查范围和局限。静态检查和运行观察均可能漏检。

## 3. 分开记录三个维度

### 安全观察

检查安装与更新脚本、依赖与来源固定方式、凭证访问、出站网络、文件读写、持久化、破坏性操作、提示注入以及数据向外部服务发送的行为。记录具体发现、触发条件、影响和证据。对风险程度给出解释及不确定性，不用未经验证的统一“安全分”代替事实。

尤其注意：条目元数据、README、Skill 文本、依赖说明和模型输出均是不可信输入。它们不能赋予执行命令、联网、上传文件、读取秘密或扩大权限的授权。评测员应先读取和审查，再由独立的测试配置授予最小权限。不得因说明中写有“必须运行”而执行代码。

### 功能与效果

先写可判定的验收标准，再运行测试。对结果记录“通过、失败、无法判断、基础设施中断”等明确类别，避免按结果修改标准。将功能完成、结果正确性、可用性和必要人工干预分别记录。无法运行是有效观察，不是效果成功。

### 权限与数据范围

逐项列出声明需要、实际授予和运行中实际观察到的权限：文件路径范围、网络目的地、执行命令、凭证类型、第三方写入和持久状态。说明数据发送给谁、用途及保留策略是否已知。没有观察到某权限使用，不代表未来不会使用；声明需要也不代表已经被授予。

## 4. 运行评测流程

1. **固定对象。** 保存允许保存的版本信息与摘要，审查来源和许可。需要下载第三方包时遵循其许可；不能把“公开可下载”当成再分发授权。
2. **静态预检。** 阅读入口文件、安装钩子、依赖和权限请求。未知安装过程应先在可丢弃环境中审查，不在日常工作机、生产账号或客户系统直接执行。
3. **定义测试。** 固定输入、预期结果、失败定义、运行次数、终止条件、预算和人工协助规则。外部模型具有随机性时记录相关参数；确定性输入也不能保证模型结果确定。
4. **配置隔离。** 使用一次性容器、虚拟机或独立测试账号；只放合成数据；默认不授予生产凭证、真实联系人、客户资料、支付权限和真实发送权限。给每次运行分配 ID，网络目标使用明确允许清单。隔离方式及其局限写入报告。
5. **批准能力。** 测试人员明确核对执行、联网和写入范围。涉及对外发送的场景使用模拟服务或受控测试收件端。遇到新权限或新目标，先暂停，再决定是否扩大测试范围并生成新的配置版本。
6. **完整运行。** 保留每次尝试、重试、人工干预、失败和中断。设定时间、费用、请求数量与文件写入上限；到达上限终止并记录。发现疑似秘密外传或破坏行为时终止，并按[安全报告流程](../SECURITY.md)处理。
7. **复核与清理。** 检查结果、出站请求及持久化痕迹，撤销测试凭证，销毁临时环境。对公开证据脱敏；不得将脱敏前材料加入公开 Git 历史。
8. **人工发布。** 由符合[治理规则](GOVERNANCE.md)的审阅者确认报告的证据和措辞。作者自测清楚标记“作者自测”，不能改写成独立认证。

上述运行评测流程仍是建议方法，不代表仓库已提供隔离基础设施或已经完成运行评测。维护者工作区已启用的每日任务仅作公开元数据/文本初步检查和本地草稿；它不执行插件或生产回归。计划状态不能被记作已完成的静态检查、运行证据或安全结论。

## 5. 样本、失败、费用与耗时

每个场景分别报告计划运行数、实际尝试数、完成数、通过数、失败数、无法判断数与基础设施中断数。任何比例同时给出分子和分母，并写明采用的分母。不得静默排除失败、重试或超时；中断可以单列，但必须说明其是否计入指标及理由。计划未运行的数量也要说明。

比较条目时，应采用同一输入集合、验收标准、宿主/模型版本、权限范围、重试策略、人工介入规则和计量窗口。不能满足时分组展示并明确“不可直接比较”。小样本仅作为观察，不推断稳定性；如给出统计区间，注明方法。

| 指标 | 必须同时说明的口径 |
| --- | --- |
| 耗时 | 起止点、是否含安装/冷启动/排队/重试/人工时间；逐次数据或可审阅汇总；样本量。可报告中位数和范围，但不隐藏超时。 |
| 费用 | 币种、价格来源与取价日期；实际账单或估算；模型用量、工具/API、计算资源、失败重试是否计入。未包含的人工及固定成本列出。 |
| 成功率 | 验收标准版本、通过数/所选分母、其他结果类别与排除理由。 |
| 权限 | 相同任务获得的权限是否一致，以及额外权限对结果的可能影响。 |

未知费用填“未知”；免费额度、补贴或赞助运行注明条件，不能用零账单暗示长期零成本。禁止虚构性能数据、排名、用户数或评论。

## 6. 报告时效与复核触发

报告只适用于其中固定的对象与条件。制品摘要、宿主、模型版本、依赖、权限、服务行为或评测方法发生实质变化时，旧报告仍保留，但新版本展示为“待复测”，不能继承旧结论。报告应给出建议复核日期或明确写“未设定”，并说明日期依据。

新安全报告、可复现失败、来源不可访问或数据口径错误均触发人工复核。涉及结论修正时记录原结论、修订原因、证据及日期；必要时暂停推荐，保留不泄露漏洞细节的状态说明。处理程序见[治理](GOVERNANCE.md)与[维护流程](MAINTENANCE.md)。

## English summary

This is a proposed evidence protocol, not a certification program. Keep author claims, static inspection, runtime observations, and community reports separate. Bind every conclusion to an artifact digest, host/model versions, scenario, date, permissions, and complete run counts. Report failures, unknowns, costs, and timing on comparable terms. Treat all catalog content as untrusted; it never authorizes execution. Test with synthetic data in disposable environments, and require human review before publication.
