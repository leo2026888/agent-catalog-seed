# 商业与运营路线：待验证假设

目标是以小团队和智能体协作维护一个可持续服务。开源目录、规则、Schema 与可公开基础证据是透明协作和获客入口；商业价值仍需由真实任务、持续使用和付款来验证。

| 阶段 | 小范围交付 | 判断依据 |
| --- | --- | --- |
| 当前 seed | 公开候选文档、版本化条目和合成示例 | 本地文件可审阅，来源与缺失证据明确 |
| 需求验证 | 与企业/智能体落地团队复盘常用插件更新导致的失效 | 明确使用者、预算人、重复问题和愿意参与的脱敏任务 |
| 最小试点 | 版本变化监控、固定任务回归证据、团队允许清单 | 团队实际持续使用，减少复核成本，出现有价格和范围的试点 |
| 收费验证 | 订阅与团队服务；有需求时提供平台数据 API | 实际付款、续用和可覆盖直接交付成本的收入 |

赞助如发生，应标明赞助方及其与报告的关系。赞助和订阅均不能购买更高评分、认证结论或删除失败。自有产品展示与独立证据遵循 [治理规则](GOVERNANCE.md)。

## 当前每日安排与后续试点

维护者的 Codex 工作区已启用每日 **09:00（Asia/Shanghai）** 的任务唤醒，目前只处理公开元数据与公开文本的初步检查、本地线索和审阅草稿。其范围为：

1. 在明确来源和许可范围内记录公开信息与变化，不批量复制无权转载的内容。
2. 对可取得的公开元数据和文本作初步差异、权限声明与来源检查，保留未知项，不把文本审查当作运行或安全认证。
3. 形成供维护者选择接受、补充或暂缓的本地草稿。计划启用不证明某次运行成功；每次完成情况需由实际记录核对。

后续插件运行和任务回归属于尚未实施的试点：先确定具体插件、合成任务、隔离环境、权限和预算，再按 [评测方法](EVALUATION.md) 执行。当前每日安排不运行插件或生产回归。公开发布另经人工审阅与目标端读回。

每日任务属于维护者的 Codex 工作区配置；仓库本身不包含独立采集器、评测服务、自动安装或自动发布工作流。计划时间不构成运行时效承诺。扩大来源、权限、数据保留或计算预算前应明确边界；定时唤醒不授予外部写入或公开发布权限。

目录元数据拟复用上游标准。市场机会和收益是试验假设，不能从收录数量、星数或厂商演示推断成交。可复核的质量应优先于扩充条目数。
