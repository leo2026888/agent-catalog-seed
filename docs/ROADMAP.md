# 商业与运营路线：待验证假设

目标是以小团队和智能体协作维护一个可持续服务。开源目录、规则、Schema 与可公开基础证据是透明协作和获客入口；商业价值仍需由真实任务、持续使用和付款来验证。

| 阶段 | 小范围交付 | 判断依据 |
| --- | --- | --- |
| 当前公开入口 | 公开网站、23条目录记录、分层评分、社区评分提交入口、本地只读MCP查询、合成 Schema 与试点申请 | Figma与Notion官方MCP及四条轮换深化复核已进入每日批次；12条候选仍为元数据初筛，实际客户端接入仍待验证 |
| 需求验证 | 与企业/智能体落地团队复盘常用插件更新导致的失效 | 明确使用者、预算人、重复问题和愿意参与的脱敏任务 |
| 最小试点 | 版本变化监控、固定任务回归证据、团队允许清单 | 团队实际持续使用，减少复核成本，出现有价格和范围的试点 |
| 收费验证 | 订阅与团队服务；有需求时提供平台数据 API | 实际付款、续用和可覆盖直接交付成本的收入 |

赞助如发生，应标明赞助方及其与报告的关系。赞助和订阅均不能购买更高评分、认证结论或删除失败。自有产品展示与独立证据遵循 [治理规则](GOVERNANCE.md)。

## 当前每日安排与后续试点

维护者的 Codex 工作区已保存并启用同一维护任务的每日双时段安排，时区为 **Asia/Shanghai**：

| 时间 | 工作范围 | 应留下的记录 |
| --- | --- | --- |
| 07:00 | 经营判断、优先级与当天计划 | 判断依据、拟办事项、预算和停止条件 |
| 07:30 | 推进已授权的产品、内容与证据工作；在自有 GitHub 和已授权公开平台完成内容检查、发布与读回 | 实际动作、成果链接、版本与证据、预算消耗、失败和待办 |

公开来源需保留许可与版本依据；文本初查不能充当运行结果或安全认证。未知插件不运行，内部材料不公开。迟触发时先按台账合并计划与执行状态，避免重复发布或重复支出。

截至 2026-09-08，该安排已完成至少一轮目录发布和目标端读回。每个日批次仍须以当日台账、发布提交和公开目标端证据单独验收。工作区所在电脑关机时不能执行；开机后补跑尚未实证。两个时段是计划时间，不是在线服务或固定分钟完成的承诺。

后续插件运行和任务回归属于按范围确认的试点：先确定具体插件、合成任务、隔离环境、权限和预算，再按 [评测方法](EVALUATION.md) 执行。未知插件与未授权生产系统不纳入日常执行。常规内容可在既定授权与质量检查范围内发布并读回；新增评测结论、权利争议与利益冲突仍按 [治理规则](GOVERNANCE.md) 审阅。

每日任务属于维护者的 Codex 工作区配置；仓库本身不包含独立自动沙箱、生产评测服务或 GitHub Actions 发布工作流。执行依据已确认的自有入口和发布范围，不能从定时唤醒推断新增权限。扩大来源、权限、数据保留或计算预算前应明确边界。

目录元数据复用公开上游字段，先批量收录，再按价值和风险进入权限文档核对、静态检查、隔离运行和真实任务评测。市场机会和收益是试验假设，不能从收录数量、公开资料评分、星数或厂商演示推断成交。目录规模与证据层级同时展示。
